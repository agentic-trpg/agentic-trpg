## 节点与文本规则

- ID 为路径 :: 限定名称 @ def 行号；不同模块、类和同名函数分别保留。嵌套函数的限定名称包含 <locals>，父函数仍保留完整原始嵌套源码，因此节点之间允许源码重叠。没有以函数名合并节点，也没有因缺 docstring 删除节点。
- S 是原始函数行切片：包括全部装饰器，从首个装饰器开始向前纳入紧邻同缩进注释，不越过空行；结束于 AST end_lineno。函数内普通注释通过 tokenizer 提取并保留，未使用 ast.unparse。模块和类 docstring 分别记录。
- T0 包含路径、限定名称、签名、所属类、字面模块／类背景各最多 400 字符及完整函数 docstring。背景只来自该文件的明确 docstring，不把架构章复制给所有函数；没有背景时留空。签名从原始 tokenizer header 提取。
- T1 为同一 T0 加当前 Codex 按源码及结构事实逐函数编写的简短中文摘要；简单访问器只说明实际动作，复杂函数说明职责、返回或状态副作用。输入签名已在 T0。摘要没有回写源码，不引入新的生成模型 API。全部 1,059 条摘要及其源码哈希、所用上下文见 [summaries.json](summaries.json)，可编辑语义源为 [summary-semantics.json](summary-semantics.json)。
- B、C 拼接时按空白规范化后的完整块与 S 去重；C 额外处理末尾 docstring 与 Summary 相邻的边界。S 函数体不重新排版。文字侧 T1 在 D、E、单独向量和 BM25 中逐字相同，没有任何组专属知识。

A=embed(S)，B=embed(S+T0)，C=embed(S+T1)，D=RRF(A,T)，E=RRF(A,BM25(T1))；T=embed(T1)。所有路线候选均为相同的 1,059 个 ID。A 有 1,029 份不同文本，其余有 1,059 份；相同源码可复用 embedding，但节点身份与排名仍独立。

## 检索及指标

固定 voyage-code-4／1024／float，document 与 query 明确区分，所有请求 truncation=false。官方 API 接口页有较旧模型名单，模型支持与上下文同时核对官方当前模型表。精确余弦以返回向量在本地 CPU float64 归一化和全候选点积计算，无近似索引或向量数据库。

BM25 使用 k1=1.2、b=0.75；中文为连续汉字的单字＋相邻双字，不依赖答案词典；英文统一小写，snake_case 拆下划线，CamelCase 与 acronym 边界拆分。查询词去重，文档保留词频，IDF=ln(1+(N-df+0.5)/(df+0.5))。这是明确支持中文的轻量切分方案，并非经过最优分词调参。无正分匹配返回空列表；本轮实际路线均达到 K，空／短列表由确定样例验证。

各路按 ID 去重取 Top-50，RRF 等权 sum(1/(60+rank))，rank 从 1 起，缺路贡献为零；先按分数降序，再按完整 ID 字典序稳定排序。最终同样比较 K=5／10。入口 Hit 是至少一个标注入口命中，MRR@10 为第一个入口的倒数，相关 Recall 的分母为该问题标注相关集合。总体使用逐问题宏平均。

Overlap=交集/K；Jaccard=交集/并集，同时保存两路实际长度和交集/min(长度)。两路均空的 Jaccard=null，不视为高重合。逐问题指标、入口及所有相关函数排名见 [questions.md](results/questions.md)，全部 Top-10 及逐问题重合见 [per-question.json](results/per-question.json)，开发／保留／全部汇总见 [summary.md](results/summary.md)。完整 Top-50、完整差集、原始响应和向量只在 .local。

## 代表性成功和失败

1. **源码已足够的入口**：Q01 总重量、Q09 移动触发机关、Q11 局部一步阻挡在中文 A 都为入口第1；保留 Q23 隐藏天气与 Q24 不确定光照也第1。Q21 的三条重量共读函数在所有路线 Top10 内。无需为这些例子额外维护摘要才能定位入口。
2. **背景／摘要帮助定位组合阅读**：Q12 固定网格占用，GridView.occupied 的 A/B/C 中文排名为 8/4/3，相关 Recall@10 从 A 2/3 到 B/C 1。Q17 保存点事实和版本恢复，RuntimeConnection.execute 从 A 第11到 B/C 第3，E 第1。Q27 库存可访问性失效从 A 第3到 B/C 第1。B 同时加入路径、签名和背景，因此不能把这些效果单独归因于模块／类背景。
3. **摘要合并仍可能降序**：保留 Q29 的 RuntimeConnection.execute，中文 A 第1、B 第6、C 第2、T 第20、D 第7、E 第1；源码已包含具体 ROLLBACK TO 和 statement_failed 分支，短摘要更容易把拒绝独立 rollback 的包装方法排前。英文扩展后 A/C/E 第1，D 仍第7。
4. **文字补回却被融合压低**：Q25 TriggerIndex.__deepcopy__ 中文 A Top50 外、T 第8、BM25 第5，D/E 变成第22／16；它是真正必要的只读索引复制语义。TriggerIndex.__getitem__ 同样由文字侧补回，但不进入融合 Top10。共同靠前的场景索引候选在 RRF 获得双路贡献，压过只在文字路出现的短方法。Q26 的局部相交读取 _touching 也是 T 独有的正确补回，融合未将它带入 Top10。
5. **需要明确调用与职责关系**：Q28 未知 COMMIT 结果，英文 A/B/C 都把 _transaction_scope 排第1；T 第11，D 降至第4。SessionMemory.pause 与 SessionRuntime.receipt 虽在文字候选池补回，但相关 Recall@10 仍只有 1/3。Q30 卸载恢复，A 找到两个入口却只召回一半相关集合；深层 release_memory 与 reconciliation 需要沿真实调用链阅读。Q18 派生结果回滚所有组都没把标注主入口放进 Top10，显示仅提高语义相似不能替代依赖追踪。

## 对六个交付问题的回答

|问题|本轮证据与试点判断|
|---|---|
|现有源码语义是否足够？|多数入口足够：A 全部中文 Hit10=0.933、保留=1.0；共读覆盖不够：全部中文 Recall10=0.619。应保留源码基线。|
|模块／类背景是否有帮助？|B 对全部中文 Recall10 有小幅改善 0.619→0.656，但 MRR 0.566→0.563；保留集 Recall10 相同。B 还含路径和签名，缺少单独背景消融，不能确认其独立收益。|
|LLM 摘要是否值得维护？|C 对全部及部分保留相关覆盖有收益，特别中文 Top5；成本重点是源码变化后的准确性维护。适合先保留高风险职责摘要，不足以证明应无条件维护全项目摘要；没有做长期维护成本或不同作者复核。|
|合并向量还是分开向量？|本轮 C 的全部 Hit5/Recall10 优于 D，保留扩展 C Recall10=0.783、D=0.750。D 中文全部 MRR 更高，却会丢失独有正确结果。当前试点更支持 C 作为候选方案，不能外推所有任务。|
|文字 BM25 足以替代文字向量？|尚不能全面替代。保留扩展 BM25 入口 Hit10=1.0，高于 T=0.8，但相关 Recall10=0.683 略低于 T=0.692；中文差距更大。融合 E 比 D 某些入口指标好，相关召回未稳定相当。低成本备用路有价值。|
|哪些更需要调用图或文档关联？|Q18 回滚与派生发布、Q25 只读索引短方法、Q28 未知COMMIT与暂停/回执、Q30 卸载/恢复多层链。需要显式调用边和现行职责/故障协议链接；本轮没有安装或声称验证完整图服务。|

## 验证、复现与局限

运行命令见 [README](README.md)。独立依赖 NumPy 2.3.5；实际使用内置 Python 3.12.14，未安装游戏依赖或改变 SM/RE 环境。核心验证包括去重、rank从1、RRF常数与同分、Top50上限、Hit/MRR/Recall、空和短重合、中文与标识符切分、无匹配空返回、装饰器/注释/嵌套/中文签名解析；只运行实验小样例，不运行游戏整套测试。具体最终验证命令和退出码见 [validation.json](validation.json)。

完整原始函数源、向量、原始批量响应、完整 Top50、临时数据和恢复预算均在被忽略的 .local/；Git 仅提交实验脚本、独立依赖、无密钥配置、固定问题/标注/摘要、汇总和可读排名。密钥只从进程环境取值，日志与产物不含密钥或请求认证头。HTTP成功但落盘前崩溃仍可能重复支付少量缺失条目；不宣称该HTTP端点提供幂等计费。不要并发运行多个 index。

样本小、标注与摘要同作者、领域和函数重叠、T0混合多种元数据、中文摘要与英文源码的语言差异、无预算匹配双路消融、无独立人工复核，使结论只能支持试点决策。源码／标注变化需要新一轮，不能继续使用本轮保留集做选择再称为最终保留结果。
